# M3 — Galaxy Z Fold6 학습 실측

기기: SM-F956N (Snapdragon 8 Gen 3, Adreno 750), Android 16.

## 학습이 동작하기까지 (v0.3.0 → v0.3.5)

| 버전 | 증상 | 원인 / 조치 |
|---|---|---|
| v0.3.0 | 학습 시작 시 `vkCreateComputePipelines: VK_ERROR_UNKNOWN` | 역전파 셰이더의 specialization constant 크기 배열 의심 → 고정 크기로 |
| v0.3.1~0.3.3 | 학습은 돌지만 어떤 설정이든 흐리고 미리보기가 안 바뀜 | 자가 검사: 순전파는 CPU와 일치, **그래디언트 전부 0** (장면 맞추기 24.9 → 24.9 dB) |
| v0.3.4 | 그대로 | 단계별 검사: 순전파 기록·갱신 단계 정상, **shared 역전파 출력만 0** (36쌍 중 1쌍). 공유 메모리 atomic은 정상 |
| v0.3.5 | **해결** | 순전파와 같은 구조의 serial 역전파(단일 반복문, 가우시안 하나씩) → 그래디언트 일치, 장면 맞추기 24.9 → 36.5 dB. 학습 전 폰 GPU에서 변형별로 검증해 맞는 것만 사용 |

- 원인이 된 구조: barrier가 **중첩 반복문** 안에 있고 반복 횟수를 공유 메모리에서 읽는 셰이더. Adreno 드라이버에서 결과가 0 (컴파일 오류 없음).
- subgroup 산술: 기능 하나씩(basic / elect / id / float add / ballot)은 컴파일되지만 조합한 셰이더(probe, 학습 역전파)는 `VK_ERROR_UNKNOWN`. 원인 조합 미확인.

## 첫 실제 학습 (v0.3.5)

lizard (점 구름 3만 개 — 배경이 거의 없는 예전 zip), 빠름: 360×640, 2000회, 배경 제거 없음.

| 항목 | 값 |
|---|---|
| 준비 | 불러오기 1.5 s · 초기화 0.2 s · GPU 준비 0.5 s · 역전파 검증 0.9 s |
| 학습 시간 | 100.7 s (2000회) |
| ms/회 (500회 단위) | 28 → 39 → 61 → 73 (가우시안 3만 → 6.5만) |
| GPU ms/회 (2000회 근처) | 투영 0.3 · 정렬 2.1 · 렌더 4.4 · **역전파 30.4** · 최적화 6.4 (합 43.6) |
| 가우시안 | 30,000 → 65,141 (densify +35,142 / −1) |
| 검증 PSNR | **21.93 dB** (23장) |
| 학습 뷰 PSNR 추이 | 12.4 → 13.6 → 13.2 → 15.5 → 18.8 → 20.3 → 21.1 → 21.1 → 21.6 → 22.4 |
| 발열 | LIGHT, 배터리 36.1°C 유지 |

관찰:
- 역전파가 GPU 시간의 70%. serial은 가우시안마다 barrier 2번 → subgroup 경로를 살리는 것이 가장 큰 속도 개선 후보.
- 벽시계 76.5 ms/회 vs GPU 합 43.6 ms → 단계마다 제출·대기 2번, 결과 읽기 등으로 약 30 ms가 GPU 밖에서 쓰임 → 단계 합치기·간접 dispatch로 줄일 수 있음 (M5).
- 처음 600회는 PSNR이 거의 그대로(SH 0차, densify 시작 전) → 학습률·스케줄 조정 여지 (M4).

## 인물 데이터셋 (v0.3.5)

body (전신 캐릭터, 마스크·깊이 있음), 빠름: 360×640, 2000회, **배경 제거 켬**.

| 항목 | 값 |
|---|---|
| 초기화 | 깊이 41,465점 → 41,465개 (0.1 s) |
| 학습 시간 | 104.9 s (2000회) |
| ms/회 (500회 단위) | 30 → 36 → 67 → 77 |
| GPU ms/회 (끝 무렵) | 투영 0.6 · 정렬 2.3 · 렌더 4.9 · **역전파 47.8** · 최적화 7.1 (합 62.7) |
| 가우시안 | 41,465 → 35,662 (densify +1,576 / 제거 −7,379) |
| 검증 PSNR | **40.10 dB** (23장, 배경 포함 — 배경은 맞추기 쉬워 인물만 잰 값보다 높게 나옴) |
| 학습 뷰 PSNR 추이 | 24.2 → 33.0 → 35.7 → 38.1 → 38.9 → 39.1 → 40.2 → 41.2 → 40.8 → 42.1 |
| 발열 | LIGHT, 배터리 36.6 → 38.3°C |

관찰:
- 인물 + 마스크 학습은 처음 200회부터 빠르게 수렴 (깊이 초기화가 좋음).
- 역전파가 lizard보다 쌍은 적은데(13.7만 vs 30만) 더 느림(47.8 vs 30.4 ms). serial 방식은 타일마다 그 타일의 가우시안 수만큼 순서대로 돌기 때문에, 인물처럼 가우시안이 몇몇 타일에 몰리면 긴 타일 몇 개가 전체 시간을 정함. 게다가 v0.3.5의 serial은 픽셀이 이미 불투명해진 뒤의(뒤쪽) 가우시안까지 다 돈다 → 타일별 "마지막 기여" 지점에서 멈추게 하면(공유 메모리 트리 최댓값은 폰에서 정상 확인) 바로 줄어들 것.
- 가우시안 수가 줄어드는데 ms/회가 늘어남: 학습이 진행되며 가우시안이 커지고 겹쳐서 타일당 쌍이 늘고, SH 차수가 0 → 3으로 올라감.

## v0.3.6: serial_cut2 (body, 배경 제거, 빠름)

| 500회 구간 | v0.3.5 serial | v0.3.6 serial_cut2 |
|---|---|---|
| 0–500 | 30 ms/회 | 98 |
| 500–1000 | 36 | 85 |
| 1000–1500 | 67 | 43 |
| 1500–2000 | 77 | 39 |
| 전체 | 104.9 s | 132.0 s |

- 결과는 동일 (검증 PSNR 40.10 → 40.03, PSNR 추이 같음).
- **타일 컷오프는 효과 큼**: 표면이 불투명해지는 후반에 77 → 39 ms.
- ~~가우시안 2개 묶음은 Adreno에서 손해~~ → 아래 표준 실행에서는 초반도 41 ms라 초반 98 ms는 설치 직후 첫 실행의 일시적 현상으로 보임 (원인 미확인). 다만 serial(30 ms)보다는 초반이 느린 것은 맞음. 어느 쪽이든 v0.3.7부터는 기기에서 재서 고름.
- 제출별: 투영 1.2/0.3 ms, 본 단계 39.2/38.1 ms (벽시계/GPU) → GPU 대기 오버헤드는 거의 없음. 앞서 추정한 "GPU 밖 30 ms"는 프로파일(패스별 따로 제출)과 평균 시점 차이로 생긴 착시.

| 검증 PSNR | **41.72 dB** (빠름 40.03) |

- 2배 학습(4000회)으로 PSNR +1.7 dB, 2000회 이후 개선은 완만 (41.6 → 43.2).
- 역전파가 여전히 GPU 시간의 77%.
