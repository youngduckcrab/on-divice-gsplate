# v0.3.2 — 배경 학습, 손상된 zip 대응, 미리보기

## 변경 사항
- **lizard 데이터셋의 점 구름을 다시 만듦** (`datasets-v1`의 `gsplat-capture-lizard.zip` 갱신 — **다시 받아 주세요**)
  - 이전 점 구름(3만 개)은 거의 조각상 위에만 있어서 공원 배경(덤불, 보도)을 학습할 수 없었습니다. 조각상 주변까지 6만 개로 다시 뽑았습니다
  - 같은 조건(90×160, 600회)에서 검증 PSNR 15.5 → 24.1 dB, 배경 색이 살아남
  - "흰색만 조금 보인다"는 증상의 주원인으로 보입니다 (은색 조각상만 학습되고 배경은 비어 있었음)
- **opacity 리셋을 기본에서 뺌**: 학습 중간에 모든 가우시안을 거의 투명하게 만들었다가 다시 학습시키는 3DGS 기법인데, 짧은 학습에서는 이득이 없었고(head·lizard 모두 비슷하거나 더 좋음) 미리보기가 갑자기 사라지는 것처럼 보였습니다
- **미리보기**: 1초마다 갱신, 몇 번째 반복의 결과인지 표시 (매 반복마다 그리면 학습이 느려져서 시간 간격으로 갱신합니다)
- **손상된 zip도 불러오기**: 일부 파일의 CRC가 틀리면 그 파일만 빼고 불러오고, 해당 프레임은 학습에서 제외합니다. 몇 개를 뺐는지 표시합니다. 프레임의 절반 이상이 손상되었으면 거부합니다

## head / body zip이 안 열리는 문제
GitHub에 올라간 zip은 다시 내려받아 검사해도 정상입니다. 폰에서 실패한 항목(`body/images/frame_00122.jpg`)은 데이터 내용 자체가 달랐습니다 — 받은 파일이 손상된 것입니다.
이번 버전은 손상된 파일만 빼고 불러오므로 우선 그대로 다시 시도해 보세요. 그래도 안 되면:
1. 내 파일 → 다운로드에서 zip의 **크기(바이트)** 를 확인해 주세요. 정상: `gsplat-capture-head.zip` **25,703,809 바이트**, `gsplat-capture-body.zip` **27,931,370 바이트**
2. 크기가 다르면 지우고 다른 브라우저(Chrome 등)로 다시 받아 주세요
3. 오류 메시지 전체를 보내 주세요 (이번 버전은 어느 파일에서 실패했는지 나옵니다)

## 테스트 체크리스트
1. 새 lizard zip(다시 받은 것)으로 **빠름** 학습 → 미리보기에 덤불·보도 같은 배경 색이 보이나요? 결과 PSNR
2. head / body 불러오기 → 되면 "손상된 파일 N개" 표시가 있는지, 안 되면 오류 메시지 전체
3. head **표준** 학습 → "요약 복사"
