# v0.16.0 — 학습 속도 개선

학습 한 회(사진 한 장으로 모델을 한 번 고치는 단계)마다 **결과는 같은데 필요 없이 하던 계산**을 줄였습니다. 화질은 그대로 두고 시간만 줄이는 것이 목표입니다.

## 바뀐 것
1. **움직임 보정 기울기 합치기**: 가우시안 128개 묶음마다 움직임 노드(64개)별로 기울기를 더합니다. 지금까지는 노드마다 스레드 하나가 묶음의 가우시안 128개를 전부 훑었습니다. 이제는 묶음의 가우시안들이 **실제로 따르는 노드만** 목록으로 만들고, 128개 스레드를 그 노드들에 나눠 가우시안을 구간별로 나눠 더합니다. 처음 가우시안들을 공간 순서(모턴 순서)로 놓아서 한 묶음이 가까운 몇 개 노드만 따르게 했습니다
   - 가까이 찍은 촬영에서 묶음 하나가 따르는 노드는 평균 9.6개(64개 중)라서, 반복 횟수가 128에서 27.8로 줄었습니다 (GPU 웨이브 64 기준)
2. **SSIM에서 배경만 있는 타일 건너뛰기**: 마스크 학습에서 타일과 그 주변에 사람 픽셀도 가우시안도 없으면 그림과 정답이 같은 배경색입니다. 그러면 SSIM은 정확히 1이고 기울기는 0입니다. 이런 타일은 계산하지 않고 값만 채웁니다. 가우시안이 없는 타일은 SSIM 기울기도 계산하지 않습니다 (아무도 읽지 않는 값이었습니다)
   - 가까이 찍은 촬영에서 타일 1620개 중 29~39%를 건너뜁니다
3. **정렬 횟수 줄이기**: 타일-가우시안 쌍(수십만 개)을 (타일, 깊이) 순서로 정렬하던 것을 이렇게 바꿨습니다
   - 가우시안(약 10만 개)을 먼저 깊이 순서로 정렬합니다
   - 그 순서대로 쌍을 만들고, 쌍은 **타일로만** 정렬합니다
   - 쌍 정렬은 7번 훑던 것이 3번으로 줄고, 대신 그보다 훨씬 적은 가우시안을 4번 훑습니다. 정렬 결과(그리는 순서)는 예전과 똑같습니다
4. **Sparse Adam**: 이번 사진에 전혀 그려지지 않은(화면 밖이거나 완전히 가려진) 가우시안은 값과 모멘트를 그대로 두고 읽기·쓰기도 하지 않습니다. 예전에는 이런 가우시안도 남은 관성으로 조금씩 움직였습니다
   - 앱의 세 설정(2000·4000·7000회)에서 켜집니다. 학습 요약 `설정` 줄에 `sparse Adam O`로 나옵니다
   - 300회처럼 아주 짧은 학습에서는 화질이 조금 낮게 나와서(PC, 다른 변경과 함께 잰 값으로 −0.4 dB) 2000회 이상에서만 켭니다
5. **검증 사진 위치 맞추기**: 검증용 사진마다 카메라 위치를 다시 맞추는 방식을 바꿨습니다
   - 시작점: 주어진 위치와 **앞뒤 학습 사진이 보정된 만큼 옮긴 위치** 중 나은 쪽에서 시작합니다 (ARCore 위치 오차는 천천히 변하기 때문)
   - 기준: L1만 씁니다. SSIM을 같이 계산하면 한 번 맞출 때 드는 비용이 두 배였습니다
   - 횟수: 20번 → 8번

## 하지 않은 것: 버킷 상태를 fp16으로 (7번)
역전파가 읽는 중간 상태를 절반 크기(fp16)로 저장해 메모리 읽기·쓰기를 줄이는 방법입니다. PC에서 학습된 모델로 기울기를 비교해 보니 **정확도가 부족했습니다**.
- 역전파는 "이 가우시안 뒤에 남은 색"을 `전체 색 − 앞쪽까지의 색`으로 구합니다. 앞쪽이 거의 다 가린 곳에서는 두 큰 수의 작은 차이라서, fp16의 반올림 오차(약 0.05%)가 그 차이를 덮어버립니다
- 측정: 학습된 모델, 사진 5장, 기울기가 있는 가우시안 232,609개(사진별 합)

| | fp32 (지금) | fp16 |
|---|---|---|
| 가우시안별 상대 오차 중간값 | 0.00006% | 0.012% |
| 오차가 10% 넘는 가우시안 | 0.001% | 5.0% |
| 오차가 기울기 자체보다 큰 가우시안 | 0% | 0.84% |

- Adam은 가우시안마다 기울기를 그 크기로 나눠 씁니다. 그래서 기울기가 작은 가우시안에서는 이 오차가 그대로 엉뚱한 방향으로 움직이는 결과가 됩니다
- 기대 이득도 한 회에 1 ms 남짓(약 2%)으로 작아서 넣지 않았습니다

## PC 확인
- 엔진 테스트 전부 통과. 새로 추가한 테스트
  - 그리는 순서: 새 정렬 결과가 (타일, 깊이, 가우시안 번호)로 정렬한 것과 **쌍 975개 모두 같음**
  - SSIM 건너뛰기: 192개 타일 중 83개를 건너뛰어도 손실이 CPU 기준값과 같음 (0.154203 / 0.154203). 가우시안에서 떨어진 곳에 사람 픽셀이 조금 있는 경우도 넣음
  - 움직임 보정 기울기: 노드 6개와 100개 모두 CPU 기준값과 같음 (오차 3e-10)
- 단계별 시간 (PC, 가까이 찍은 가상 촬영 853×480, 위치·움직임·노출 보정 켬)

| | v0.15.1 | v0.16.0 |
|---|---|---|
| 정렬 (쌍) | 154~201 ms | 87~123 ms |
| 투영 (+ 가우시안 깊이 정렬) | 6~10 ms | 25~34 ms |
| 최적화의 기하 단계 (움직임 보정 포함, 같은 모델) | 26.2 ms | 17.9 ms |
| 검증 22장 (위치 맞추기 포함) | 약 1400 s | 536 s |
| 위치 맞추기로 오른 검증 PSNR | +0.26 dB | +0.26 dB |

- Sparse Adam 켬/끔 비교 (PC, 같은 촬영 427×240, 2000회, 나머지는 같음)

| | 끔 | 켬 |
|---|---|---|
| 검증 PSNR (위치 맞춘 뒤) | 37.79 dB | 37.78 dB |
| 검증 PSNR (주어진 위치) | 36.07 dB | 36.34 dB |
| 머리 PSNR | 32.94 dB | 32.96 dB |
| SSIM | 0.9842 | 0.9841 |

- PC는 GPU를 CPU로 흉내 내서 단계별 비율이 폰과 다릅니다 (역전파가 대부분). 실제로 얼마나 빨라졌는지는 폰에서 확인해야 합니다
