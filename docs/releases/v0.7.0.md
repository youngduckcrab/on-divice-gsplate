# v0.7.0 — 실제 촬영 학습 속도 수정 + 카메라 위치 보정

첫 실제 촬영(S24 Ultra, 170장) 결과에서 나온 문제 두 가지를 고쳤습니다.

## 1. 속도
- **빠른 역전파(bucket)가 다시 켜집니다**
  - 실제 촬영은 사람이 화면을 꽉 채워 처음 15만 개 가우시안이 커서, 학습 초반에 타일-가우시안 쌍이 70만 개를 넘었습니다
  - 쌍 버퍼가 그만큼 커진 뒤 줄지 않아 bucket용 버퍼가 GPU 한도(128 MB)를 넘었고, 끝까지 느린 방식으로 학습했습니다(요약의 `bucket 1000000…`)
  - 이제 500회마다 하는 역전파 재선택 때 버퍼를 최근 쌍 수에 맞게 줄여서 bucket이 다시 쓰입니다
- **초기화 4.7 s → 1 s 안쪽 예상**
  - 가장자리에서 번진 깊이 점 때문에 이웃 찾기가 느려졌던 문제를 고쳤습니다(PC 10 s → 0.7 s)

## 2. 카메라 위치 보정 (새 기능)
- 학습하면서 **사진마다 카메라 위치·방향의 작은 오차를 고칩니다**
  - ARCore 위치는 cm 단위로 틀릴 수 있고, 그러면 결과가 흐려지거나 겹쳐 보입니다
- 학습 탭에 **카메라 위치 보정** 스위치가 생겼습니다
  - 직접 찍은 스캔은 기본으로 켜집니다
  - 가상 데이터셋은 위치가 정확해서 꺼집니다
- 검증 사진도 평가 전에 위치를 맞춘 뒤 점수를 냅니다(맞추기 전 점수도 함께 표시). 그래서 평가가 몇십 초 더 걸릴 수 있습니다
- 요약에 새 줄이 나옵니다
  - `카메라 위치 보정: …회 · 이동 평균 … cm · 회전 평균 …°`
  - `검증 PSNR … (검증 사진도 위치 맞춘 뒤; 원래 위치로는 … dB)`

### PC 확인 (가상 촬영에 위치 오차를 넣어서)
| 위치 오차 | 보정 없음 | 보정 |
|---|---|---|
| 평균 0.8 cm | 35.0 dB | **39.7 dB** |
| 평균 2.4 cm (최대 3 cm) | 28.6 dB | **35.1 dB** |

- 사진끼리 어긋나는 정도(재투영 오차)가 약 10배 줄었습니다: 6.1 → 0.6 픽셀
- 정확성 검사: 계산한 보정 방향이 다른 방법으로 구한 값과 4자리까지 같았습니다
- 정확성 검사: 일부러 10 cm 옮긴 카메라가 제자리(0.0 cm)로 돌아왔습니다
- 위치가 원래 정확한 데이터에서는 0.6 dB 손해라서, 직접 찍은 스캔에서만 기본으로 켭니다

## 부탁드리는 것
같은 사람을 다시 찍거나, 이미 저장된 `scan-20261031-170043`으로:
1. **표준 · 카메라 위치 보정 켜고** 학습 → "요약 복사"
   - 학습 시간
   - 역전파 실측 줄에 bucket 숫자가 나오는지
   - 검증·머리 PSNR
   - 카메라 위치 보정 줄
2. 가능하면 같은 스캔으로 **보정 끄고** 한 번 더 → "요약 복사" (보정 효과 비교)
3. 뷰어에서 얼굴이 전보다 선명한지
