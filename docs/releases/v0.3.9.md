# v0.3.9 — 학습 중 역전파 재선택, 타원 타일 판정

v0.3.8 결과: subgroup_lane4(13.3 ms)·subgroup_lane1(14.0 ms)이 **폰에서 처음으로 컴파일되고 그래디언트도 맞았지만**, serial_cut(8.9 ms)보다 느려 serial_cut이 쓰였습니다. 같은 코드인데 빠름이 75 s(v0.3.7) → 104.5 s로 느려졌고, 역전파만이 아니라 모든 단계가 같이 ~1.7배 느려져 GPU 클럭 상태 차이로 보입니다.

## 변경 사항
- **학습 중 역전파 방식 재선택**
  - 지금까지는 학습 전에 작은 합성 장면(가우시안 1.2만 개)으로 한 번 재서 정했습니다. 실제 학습은 가우시안이 늘고 GPU 클럭도 바뀌어서, 처음에 빠른 방식이 나중에는 느릴 수 있습니다
  - 이제 **20회째와 그 뒤 500회마다**, 그래디언트가 맞는 방식들을 **같은 실제 학습 단계에서** 번갈아(A B C C B A 순서) 재고 가장 빠른 것으로 바꿉니다
  - 모든 후보가 CPU 기준과 같은 그래디언트를 내는 것을 검증받은 방식이라 바꿔도 학습 결과는 같습니다. 재는 비용은 전체의 1~2% 정도입니다
  - "요약 복사"에 `역전파 실측` 줄이 생깁니다: 처음 잰 결과, 바뀐 시점, 마지막 결과
- **타원 타일 판정**
  - 가우시안이 맡는 타일을 "가장 긴 축 반경의 원을 감싼 사각형" 대신, **alpha ≥ 1/255인 타원이 실제로 닿는 타일만** 셉니다. 길쭉한 가우시안일수록 빈 타일이 많이 빠집니다
  - 쌍이 줄면 정렬·렌더·역전파·최적화가 모두 같이 가벼워집니다. 기여가 있는 픽셀은 하나도 빠지지 않아 렌더와 그래디언트는 그대로입니다(테스트로 확인)
  - 두 셰이더가 같은 타일을 세는지 확인하는 `타일 불일치` 수가 요약의 학습 줄에 나옵니다. **0이어야 정상**입니다

## PC(lavapipe) 확인
- 테스트 장면: 필요한 쌍 665 = 만든 쌍 665 (예전 방식 1102, −40%), 빠진 타일 0, 중복 0, 불일치 0
- 재선택: 모든 방식을 같은 단계에서 돌려도 그래디언트 차이 0
