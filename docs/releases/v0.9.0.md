# v0.9.0 — 화질: 원인 진단 + 밝기·색 보정

실제 스캔(Fold6, v0.8.1)은 검증 31.2 dB · 머리 24.0 dB였습니다. 그런데 **학습에 쓴 사진조차 30~32 dB밖에 못 맞췄습니다**(가상 데이터는 40 dB 근처). 모델이 부족해서라기보다 **사진끼리 서로 안 맞기 때문**일 가능성이 큽니다. 그래서 무엇이 안 맞는지 재는 진단을 넣고, 그중 확실하게 고칠 수 있는 것부터 고쳤습니다.

## 1. 진단 (학습 요약에 `진단 ·` 줄 3개)
학습이 끝나면 모든 사진을 모델로 다시 그려서 실제 사진과 비교합니다(5초 정도 더 걸림).
- **사진별 밝기**: 사진마다 모델보다 몇 배 밝은지, 색조가 얼마나 다른지
  - 폰 카메라는 자동 노출·화이트 밸런스를 끌 수 없어서, 도는 방향에 따라 사람이 밝아지거나 어두워집니다
  - "사진마다 밝기·색을 맞추면 사람 안쪽 PSNR … → … dB"는 그걸 맞췄을 때 얼마나 좋아질지입니다
- **오차 위치**: 마스크 경계, 윤곽 불일치, 사람 안쪽(머리), 배경 중 어디에 오차가 몰려 있는지
- **흐린 사진** 비율과 **가장 안 맞는 사진** 3장(번호, 밝기, 선명도)

## 2. 밝기·색 보정 (새 스위치, 직접 찍은 스캔은 기본 켬)
- 사진마다 R·G·B 밝기 배율을 하나씩 두고, 학습하면서 "이 사진은 모델보다 6% 밝다"를 계산해 사진을 맞춰서 학습합니다
- 전체 밝기 기준은 모든 사진의 평균으로 고정합니다
- 요약에 `밝기·색 보정: …회 · 사진별 밝기 …~…배 · 색조 차이 …%` 줄이 나옵니다

## PC 확인
가상 촬영(가만히 선 사람, 90장)에 일부러 문제를 넣어 확인했습니다.

| 넣은 문제 | 검증 PSNR | 머리 | 진단이 보여 준 것 |
|---|---|---|---|
| 없음 | 41.2 dB | 33.0 dB | 밝기 차이 0.2%, 오차의 85%가 마스크 경계 |
| 자동 노출·화이트 밸런스 변화(밝기 ±12%, 색 ±4%) | 40.6 dB | 32.8 dB | 밝기 차이 1.8%, "맞추면 +1.3 dB" |
| → **밝기·색 보정 켬** | **41.2 dB** | **33.0 dB** | 남은 밝기 차이 0.1% |
| 마스크 경계가 사진마다 ±4 px 흔들림 | **31.2 dB** | **23.9 dB** | 오차의 96%가 마스크 경계 |

- 밝기·색 보정은 문제없는 데이터에서는 손해가 없습니다(41.20 → 41.14 dB)
- **마스크 경계 흔들림이 실제 스캔 숫자(31.2 / 24.0 dB)를 거의 그대로 재현합니다.** 지금 가장 의심되는 원인입니다
  - ML Kit 인물 분할은 내부적으로 작은 해상도(256)로 계산해서 머리카락·손 경계가 사진마다 몇 픽셀씩 다릅니다
  - 학습 쪽에서 막아 보려고 두 가지를 시도했는데 둘 다 효과가 없어서 넣지 않았습니다
    - 경계 근처는 학습에서 빼기: 오히려 나빠짐(36.1 → 33.7 dB)
    - 중간에 마스크를 모델이 그린 윤곽으로 바꾸기: 변화 없음
  - 배경까지 같이 학습한 뒤 사람만 잘라 내는 방법은 한 회가 약 5배 느려져서 보류했습니다
  - 마스크 자체를 더 정확하게 만드는 쪽(예: 사람·머리 주변을 잘라 더 큰 해상도로 분할)이 다음 후보입니다. 이번 진단 결과로 정하겠습니다
