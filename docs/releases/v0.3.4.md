# v0.3.4 — 역전파가 0을 내던 문제 수정 시도 + 단계별 진단

v0.3.3 자가 검사로 원인이 좁혀졌습니다. 폰에서 **순전파(렌더링)는 정확**한데(이미지 차 0.002, loss가 CPU와 소수 5자리까지 같음) **그래디언트가 전부 0**이었습니다. 그래서 학습이 시작 상태에서 전혀 움직이지 않았고(PSNR 추이 12 → 12, 장면 맞추기 24.9 → 24.9 dB), 어떤 설정이든 결과가 같았습니다.

## 변경 사항
- **역전파에서 공유 메모리 atomicMax를 없앰**: 타일마다 "몇 번째 가우시안까지 거슬러 올라갈지"를 atomicMax로 구했는데, 이 값이 0이 되면 정확히 지금 증상(모든 그래디언트 0)이 납니다. 원자 연산 없이 공유 메모리 트리로 최댓값을 구하도록 바꿨습니다
- **빠른 역전파를 하나 더 시도**: 드라이버가 subgroup 버전을 거부해서(VK_ERROR_UNKNOWN) 느린 대체 방식으로 돌았습니다(1회 214 ms 중 역전파가 173 ms). vote 연산을 빼고, 벡터 대신 스칼라 subgroupAdd를 쓰는 버전을 추가해 차례로 시도합니다
- **자가 검사 강화**
  - GPU 기본 연산 검사: 공유 메모리 atomicMax / atomicAdd / 트리 최댓값, subgroup 합 (컴파일되는지, 값이 맞는지)
  - 단계별 검사: 순전파 기록(픽셀별 기여 수) → 역전파 출력(0이 아닌 쌍 수, 색 그래디언트) → 파라미터 갱신 단계. 다시 틀리면 어느 단계인지 바로 보입니다
  - subgroup(벡터) · subgroup(스칼라) · shared 세 방식 모두 검사
